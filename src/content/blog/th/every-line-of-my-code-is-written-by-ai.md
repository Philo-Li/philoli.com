ในฐานะวิศวกรซอฟต์แวร์ที่ทำงานมานานกว่า 6 ปี ผมไม่ได้ลงมือเคาะโค้ดเองสักบรรทัดมาปีกว่าแล้ว โปรเจกต์ปัจจุบันที่ทำอยู่ โค้ดทุกบรรทัดเขียนโดย AI ล้วนๆ แต่ถ้าย้อนกลับไปตอนที่เริ่มใช้ AI เขียนโค้ดครั้งแรกเมื่อปีก่อน... ช่วงเวลาที่ผมรู้สึกฟินกับมันอยู่ได้ไม่ถึงสามวันด้วยซ้ำ

<!--more-->

## ความฟินของการ Vibe Coding

ผมยังจำช่วงเดือนมิถุนายนปีที่แล้ว (2025) ได้ดี ตอนที่เปิดลองใช้ Cursor เป็นครั้งแรกเพราะได้ยินชื่อเสียงมาหนาหู แวบแรกหน้าตามันก็เหมือน VS Code ตัวเก่งที่คุ้นเคย แค่มีแถบข้างสำหรับคุยกับ AI เพิ่มเข้ามา

ก่อนหน้านั้น ภาพจำเรื่อง AI Coding ของผมยังหยุดอยู่แค่พวก auto-complete ฉลาดๆ อย่าง Copilot แต่พอผมลองพิมพ์พรอมต์แรกแล้วกดยิงให้มัน สิ่งมหัศจรรย์ก็เกิดขึ้นตรงหน้า AI กำลังคิดอย่างบ้าคลั่ง แล้วสาดโค้ดออกมาหลายสิบหลายร้อยบรรทัดลงบนเอดิเตอร์อย่างไว มันสลับไฟล์ไปมาเพื่อแก้โค้ดได้เอง แถมยังสั่งรันคำสั่งใน Terminal ให้เสร็จสรรพ

แค่บอกความต้องการเป็นภาษามนุษย์ธรรมดาๆ AI ก็เนรมิตฟีเจอร์นั้นขึ้นมาได้ทันที ไม่จำเป็นต้องมานั่งพิมพ์ทีละบรรทัดอีกต่อไป นี่ไม่ใช่แค่การช่วยเติมคำอัตโนมัติแบบเดิมๆ แล้ว แต่มันคือการเข้ามารับช่วงต่องานของวิศวกรซอฟต์แวร์ไปส่วนหนึ่งจากมุมมองที่สูงกว่าเดิม

วินาทีนั้น ผมรู้สึกเหมือนตัวเองถือพู่กันวิเศษของหม่าเหลียง มันเป็นความปีติเหมือนได้มองเห็นประตูบานใหม่เปิดออกสู่โลกอีกใบ

ตอนนั้นผมถึงกับโพสต์ความรู้สึกลงไปว่า:

> Vibe Coding นี่มันเกิดมาเพื่อคนเป็น ADHD ชัดๆ วิธีเขียนโค้ดแบบเดิมมันขัดกับธรรมชาติของชาว ADHD สุดขั้ว แต่ Vibe Coding มารักษาอาการขี้เกียจเขียนเทสต์ แอนตี้การแต่ง CSS สะกดชื่อตัวแปรผิดประจำ หรือความเบื่อหน่ายเวลานั่งงมแก้บั๊กซ้ำซากพวกนี้จนหายปลิดทิ้ง
>
> พอดึง AI เข้ามาช่วย ทุกอย่างเห็นผลลัพธ์ไวมาก ความฟินและไฟในการทำงานพุ่งกระฉูด ยิ่งงานซ้ำซากจุกจิกเท่าไหร่ AI ยิ่งทำได้เนียนกริบ
>
> หน้าที่ของเราเหลือแค่คุมทิศทางใหญ่ๆ ออกแบบสถาปัตยกรรม (Architecture) วางตัวเป็นผู้นำโปรเจกต์อย่างต่อเนื่อง
>
> เอาจริงๆ ผมไม่ได้อยากนั่งเคาะแป้นพิมพ์ทีละตัวอักษรหรอก แต่ผมหลงใหลในความสุขของการสร้างผลงาน ตั้งแต่ยุคภาษาแอสเซมบลีจนมาถึงภาษาระดับสูง ประสบการณ์ของโปรแกรมเมอร์ในการสร้างระบบควรจะดีขึ้นเรื่อยๆ และมีประสิทธิภาพสูงขึ้นเรื่อยๆ อยู่แล้ว
>
> การได้สร้างสรรค์ซอฟต์แวร์ในฐานะ “ผู้สร้าง” อย่างแท้จริง โดยไม่ต้องรู้สึกเหมือนเป็น “จับกังแบกอิฐ” เขียนโค้ดไปวันๆ ในมุมของโปรแกรมเมอร์แล้ว มันคือความสุขขั้นสุดเลยล่ะ

## ขีดจำกัดของ Vibe Coding

รูปแบบการเขียนโค้ดแบบนี้มีชื่อเรียกเฉพาะว่า “Vibe Coding” เป็นคำที่ Andrej Karpathy ผู้ร่วมก่อตั้ง OpenAI บัญญัติขึ้นเมื่อเดือนกุมภาพันธ์ 2025 หัวใจของมันคือการปล่อยใจไปตามมู้ด (Vibe) ล้วนๆ: สั่ง AI ด้วยภาษาพูดว่าอยากได้อะไร AI เจนโค้ดอะไรมาก็กดรับหมด ไม่ต้องมานั่งตรวจทีละบรรทัด พอเจอบั๊กหรือ error ก็โยนกลับไปให้ AI แก้ต่อ วนไปเรื่อยๆ จนแทบจะลืมไปเลยว่ามีโค้ดอยู่จริง

แต่หลังจากปล่อยโพสต์อวยยศข้างต้นไปได้ไม่ทันพ้นสามวัน ผมก็ชนเข้ากับ “กำแพง” ของ Vibe Coding เต็มๆ

ตอนนั้นผมกำลังทำต้นแบบ (Prototype) แอปตัวหนึ่งอยู่ ด้วยความที่ Vibe Coding เพียวๆ ปล่อยให้ AI ออกแบบตามใจชอบจากคำสั่งกว้างๆ โดยไม่ได้ใส่หลักการทางวิศวกรรมซอฟต์แวร์เข้าไปเลย ผลที่ได้คือ พอนานเข้า AI เริ่มออกทะเลและคุมไม่อยู่ สถาปัตยกรรมของระบบเละเทะยุ่งเหยิงจนเกินเยียวยา

สุดท้ายผมตัดสินใจล้างไพ่ รื้อทำใหม่หมด คราวนี้สวมหมวกวิศวกรซอฟต์แวร์เต็มตัว แล้ววางกระบวนการทำงานมาตรฐาน (Standard Workflow) เข้าไปประกบกับการพัฒนาโดยมี AI ช่วย

การทำรอบสองนี้พาผมเข้าสู่สภาวะใหม่ มันยังคงความสนุกเร้าใจแบบ Vibe Coding ไว้อย่างครบถ้วน แต่เสริมทัพด้วยการทำ Code Review ที่เข้มงวด เอกสารกำกับที่ชัดเจน และการซอยงานให้เป็นชิ้นเล็กๆ ค่อยๆ ปรับแก้ไปทีละจุด (Incremental changes) แทนที่จะยัดฟีเจอร์ใหญ่ๆ ตูมเดียว ผลคือระบบโดยรวมและโค้ดที่ออกมาอยู่ในการควบคุมอย่างเบ็ดเสร็จ สั่งอะไรก็ได้ดั่งใจ ความรู้สึกของการมี AI ช่วยงานเริ่มกลายเป็นการทำหน้าที่เหมือนลีดที่คอยไกด์งานให้นักศึกษาฝึกงานเก่งๆ สักคน เราไม่ต้องลงมือทำดีเทลหยุมหยิมเอง แต่ยังคงต้องถือหางเสือด้านโครงสร้างและคิดภาพรวมให้ออก

หลังจากนั้นไม่นาน ผมเปลี่ยนมาใช้ Claude Code ในการช่วยพัฒนา ซึ่งให้การควบคุมที่แม่นยำและทรงพลังกว่าเดิมมาก เหมือนติดปีกให้ตัวเอง ทำให้ความเร็วในการพัฒนาเพิ่มขึ้นหลายเท่าตัว

## อนาคตของวิศวกรซอฟต์แวร์

“เป็นไปได้ไหมที่ Vibe Coding จะทำให้คนเราปั้นของออกมาเสร็จไวเกินไป จนหมดไฟที่จะลงลึกไปศึกษาพื้นฐานการเขียนโปรแกรมจริงๆ?”

ผมตอบได้ทันทีเลยว่า: เป็นไปได้อย่างยิ่ง!

เส้นทางดั้งเดิมจากการหัดเขียนโค้ดไปสู่การทำโปรดักต์ มันเหมือนการขึ้นบันไดทีละขั้น หลายคนเริ่มจากคอร์สไวยากรณ์ภาษาพื้นฐาน ก้าวขึ้นมาเป็นจูเนียร์เอนจิเนียร์ (Junior Engineer) ลุยงานจริง เจอปัญหาจริงในโปรดักชัน จนค่อยๆ เติบโตกลายเป็นวิศวกรที่พึ่งพาตัวเองได้ ทุกย่างก้าวจะได้รับฟีดแบ็กสม่ำเสมอ ด้วยระดับการเรียนรู้ของคนทั่วไป เส้นทางสายนี้จึงมีแบบแผนชัดเจนและเข้าถึงได้ไม่ยากนัก

แต่ Vibe Coding ได้ทุบกำแพงเริ่มต้นจนราบเป็นหน้ากลอง เดี๋ยวนี้ใครๆ ก็เนรมิตของระดับ Demo ออกมาได้สบาย ทว่า “วิศวกรรมซอฟต์แวร์” เป็นศาสตร์ที่ต้องอาศัยการลงมือปฏิบัติจริงอย่างมหาศาล การเปลี่ยนจากแค่ Demo ไปเป็นโปรดักต์ระดับโปรดักชันที่พร้อมใช้งานในเชิงพาณิชย์และเสถียรพอ มันคือระยะห่างระหว่างการทำ 0 ไป 1 กับการทำ 1 ไป 100

ในระบบอาชีพแบบเดิม คนที่พาโปรเจกต์จาก 0 ไป 1 ได้ มักจะสั่งสมวิชาพื้นฐานที่จำเป็นต่อการไปต่อถึง 100 มาด้วยตลอดทาง แต่ Vibe Coding ไม่ได้มอบทักษะรากฐานเหล่านั้นให้กับมือใหม่ พอจะก้าวจาก 1 ไป 10 ก็ต้องเจอกับหน้าผาความยากที่ตัดขาดจากเดิม จนคนส่วนใหญ่ถอดใจเลิกไปต่อ

เพียงเพราะช่วงเริ่มต้นมันง่ายดายเกินไป พอมาเจอกำแพงหินข้างหน้า ลำพังแค่ความชอบหรือความสามารถในการเรียนรู้ระดับมาตรฐานจึงข้ามไปไม่พ้น ส่วนคนที่ข้ามมันไปได้อย่างสบายๆ แปลว่าเขามีสกิลการเรียนรู้ การลงมือทำ และการแก้ปัญหาในระดับท็อปฟอร์มอยู่แล้ว—อย่างน้อยๆ ก็ระดับ Top 1% ของคนในวงการ

พูดง่ายๆ คือ คนหัวกะทิกลุ่มนี้ ต่อให้อยู่ในยุคก่อนมี AI เขาก็มีความสามารถพอที่จะก้าวขึ้นเป็นวิศวกรแถวหน้าได้อยู่ดี

เมื่อความสามารถในการเขียนโค้ดของ AI ก้าวกระโดด อุตสาหกรรมก็แทบไม่ต้องการวิศวกรระดับจูเนียร์อีกต่อไป ห่วงโซ่การบ่มเพาะคนทำงานจะขาดตอน และพื้นที่สำหรับให้มือใหม่ได้ฝึกปรือลับคมฝีมือก็จะเหลือน้อยลงเรื่อยๆ

หนึ่งปีให้หลังนับจากวันที่ผมเริ่มร่างบทความนี้ ตัวเลขจากตลาดแรงงานก็เริ่มตอกย้ำข้อสังเกตดังกล่าวอย่างชัดเจน:

- ห้องปฏิบัติการเศรษฐกิจดิจิทัลของสแตนฟอร์ด (Stanford Digital Economy Lab) ใช้ข้อมูลเงินเดือนจาก ADP ของสหรัฐฯ พบว่า ณ เดือนมิถุนายน 2026 ในกลุ่มอาชีพที่ได้รับผลกระทบจาก AI มากที่สุด ตัวเลขการจ้างงานของคนรุ่นใหม่อายุ 22–25 ปี ต่ำกว่าแนวโน้มของคนวัยเดียวกันในอาชีพอื่นๆ ถึง 19% (จากเดิมที่ห่างอยู่ 15% เมื่อปีก่อน) ในขณะที่แรงงานสายมีประสบการณ์ไม่ได้รับผลกระทบนี้เลย และช่องว่างนี้เกิดจากการที่บริษัท “รับเด็กใหม่น้อยลง” ไม่ใช่การเลิกจ้างคนเดิม ([Stanford Digital Economy Lab, 2026-08](https://digitaleconomy.stanford.edu/news/canariesaug26/))
- รายงานเดือนมิถุนายน 2026 จากกองทุน VC SignalFire ชี้ว่า บริษัทยักษ์ใหญ่เทคโนโลยี 12 แห่ง เช่น Google, Meta, Apple, Microsoft ลดการเปิดรับเด็กจบใหม่และตำแหน่งระดับเริ่มต้นลงถึง 65% เมื่อเทียบกับปี 2019 ส่วนสตาร์ทอัพระยะเริ่มต้น (Early-stage) ยิ่งลดฮวบลงไปถึง 76% ([SignalFire State of Talent Report 2026](https://signalfire.com/blog/signalfire-state-of-talent-report-2026))
- สถิติจากเว็บไซต์จัดหางาน Indeed เผยว่า ในไตรมาสแรกของปี 2026 ตำแหน่งงานด้านพัฒนาซอฟต์แวร์ในสหรัฐฯ มีตำแหน่งระดับจูเนียร์เปิดรับเพียงแค่ 4.5% เท่านั้น ซึ่งถือว่าต่ำที่สุดในบรรดาทุกสายอาชีพ ([Indeed Hiring Lab, 2026-07](https://hiringlab.indeed.com/2026/07/23/the-labor-market-is-tilting-toward-seniority/))

ผมค่อนข้างมองอนาคตของวงการนี้ในแง่ร้าย ภาพของสายงานเขียนโปรแกรมกำลังแตกขั้วอย่างรุนแรง ฝั่งหนึ่งคือสังเวียนของเหล่าทวยเทพยอดฝีมือปะทะกัน ส่วนอีกฝั่งคือผู้คนที่ทำของเล่นระดับ Demo เล่นๆ ตามความสนใจ

และสายงานอื่นๆ ก็คงค่อยๆ เดินตามรอยนี้เช่นกัน ในโลกอนาคต งานที่ใช้พลังสมองระดับเบาถึงปานกลาง (Light cognitive work) คงถูก AI กลืนกินจนหมดสิ้น

แม้แต่วงการคณิตศาสตร์ที่ขึ้นชื่อว่าต้องอาศัยความคิดสร้างสรรค์ระดับออริจินัลสูงสุด ก็ยังโดน AI เจาะแตกไปเรียบร้อยในปีนี้:

- มกราคม 2026: Kevin Barreto นักศึกษาปริญญาตรีจากเคมบริดจ์ ร่วมกับ Liam Price ผู้หลงใหลคณิตศาสตร์ ได้อาศัย GPT-5.2 Pro ไขปริศนาปัญหาข้อที่ 728 ของ Erdős (Erdős Problem #728) สำเร็จ ทั้งที่ก่อนหน้านี้ไม่มีเปเปอร์ไหนเคยพิสูจน์ได้ นับเป็นปัญหาของ Erdős ข้อแรกที่ถูกพิสูจน์โดย AI เป็นหลัก
- พฤษภาคม 2026: โมเดลของ OpenAI ล้มข้อสันนิษฐานระยะทางหนึ่งหน่วย (Unit distance conjecture) ที่ Erdős เสนอไว้ตั้งแต่ปี 1946 ได้สำเร็จ ซึ่งเป็นโจทย์ที่ค้างคาวงการคณิตศาสตร์มานานถึง 80 ปี Tim Gowers นักคณิตศาสตร์รางวัลฟิลด์สมีเดล ถึงกับออกปากว่า “ไม่เคยมีบทพิสูจน์ที่สร้างโดย AI ตัวไหนเข้าใกล้ระดับนี้มาก่อน” และหลังจากนั้นไม่กี่สัปดาห์ ทีมนักคณิตศาสตร์ที่เป็นมนุษย์ก็นำผลลัพธ์ของ AI ไปต่อยอดปรับปรุงให้สมบูรณ์ขึ้นไปอีกขั้น
- ในเดือนเดียวกัน AI Agent ของ Google DeepMind แก้โจทย์คณิตศาสตร์ปลายเปิดได้เองถึง 9 ข้อจากทั้งหมด 353 ข้อ โดยใช้ต้นทุนเพียงไม่กี่ร้อยดอลลาร์ต่อโจทย์หนึ่งข้อ
- ยิ่งไปกว่านั้น นักคณิตศาสตร์ระดับตำนานอย่าง Noga Alon ถึงกับประกาศเลิกทำวิจัยเรื่องปัญหาของ Erdős ไปเลย โดยบอกว่า “พอ AI เริ่มแก้พวกมันได้ การทำต่อก็หมดความหมายไปแล้ว”

## ซีรีส์นี้จะเล่าถึงอะไรบ้าง

ทุกวันนี้ เมื่อคนที่ไม่เคยมีพื้นฐานการเขียนโค้ดเริ่มหันมาลอง AI Coding กันเยอะขึ้น หลายคนอาจจะยังจับต้นชนปลายไม่ถูก หรือทำได้แค่โปรเจกต์เล็กๆ แล้วก็ตัน พวกเขาจะเริ่มพบว่า การขาดความรู้ด้านวิศวกรรมซอฟต์แวร์ทำให้ไม่รู้ว่าตัวเองกำลังทำอะไรอยู่ ย่อยปัญหาไม่เป็น ไม่รู้วิธีจัดการกับความซับซ้อน และไม่รู้จะสั่ง AI ยังไงให้ได้ผลลัพธ์ตามเป้า

นอกจากนี้ ผมยังสังเกตเห็นว่า ปัญหาของอีกหลายคนเกิดจากการขาดการคิดเชิงตรรกะ ไม่รู้วิธีตั้งคำถาม ขาด Critical Thinking และไม่รู้ด้วยซ้ำว่าสิ่งที่ AI ตอบกลับมานั้นถูกหรือผิด

ในฐานะวิศวกรซอฟต์แวร์ที่มีประสบการณ์กว่า 6 ปี ผมใช้ AI ช่วยออกแบบและพัฒนาโปรเจกต์ที่มีความซับซ้อนมาแล้วหลายตัว ซึ่งโปรดักต์เหล่านั้นก็มีผู้ใช้งานจริงอยู่พอสมควร อย่างที่ผมเกริ่นไว้ตอนแรก ทุกบรรทัดในโค้ดปัจจุบันของผม AI เป็นคนเขียนหมด AI ช่วยสร้างโปรเจกต์ซับซ้อนได้จริง แต่มีข้อแม้ว่าตัวคนพัฒนาต้องรู้ตัวว่ากำลังทำอะไรอยู่ และต้องรู้วิธีชี้แนะให้ AI ทำงานให้เสร็จ AI เป็นเพียงเครื่องมือ หัวใจสำคัญยังคงอยู่ที่ “คน”

ในยุคของ AI วิถีการเรียนเขียนโค้ดแบบเดิมๆ กำลังจะถูกรื้อทิ้ง เพื่อให้ก้าวทันกับคลื่นลูกนี้ ผมจึงตั้งใจจะเปิดซีรีส์บทความชุด **《คู่มือ Vibe Coding ฉบับจับมือทำตั้งแต่ศูนย์》**

เนื้อหาในคู่มือชุดนี้จะครอบคลุมหลายพาร์ตสำคัญ:

1. **ผสาน AI Coding เข้ากับ Best Practices ของวิศวกรรมซอฟต์แวร์ยุคใหม่**: เริ่มตั้งแต่ปูความเข้าใจว่าวิศวกรรมซอฟต์แวร์คืออะไร แล้วค่อยๆ เริ่มจากศูนย์เพื่อปั้นซอฟต์แวร์ในฝันออกมาด้วยตัวเอง เป้าหมายคือโปรเจกต์ต้องไม่หยุดอยู่แค่ Demo แต่ต้องดูแลรักษาได้ในระยะยาว และมีกระบวนการทำงานที่ลื่นไหลไร้รอยต่อ
2. **คู่มือฝึกวิธีคิดและตรรกะ**: รู้วิธีตั้งคำถามอย่างมีประสิทธิภาพเวลาทำ AI Coding, สิ่งที่ควรเลี่ยง และวิธีเขียน Documentation โปรเจกต์ให้ชัดเจนเพื่อคุมทิศทาง AI
3. **การทดสอบโค้ดและปรับแต่ง Workflow**: รู้วิธีเขียน Test และจูนกระบวนการทำงาน เพื่อรักษาโครงสร้างระบบให้มั่นคง ไปพร้อมๆ กับการยกระดับคุณภาพและฟังก์ชันการทำงานอย่างต่อเนื่อง ทำอย่างไรให้พัฒนาได้เร็วขึ้นโดยไม่แลกกับคุณภาพโค้ด และการวาง Automated Workflow
4. **การเลือก Tech Stack ที่เหมาะกับ AI ที่สุด**: ควรเลือกภาษาและเฟรมเวิร์กไหนมาพัฒนา ถึงจะดึงศักยภาพและความเก่งของ AI ออกมาได้เต็มเม็ดเต็มหน่วยที่สุด

## ส่งท้าย

อันที่จริงเนื้อหาหลักของบทความนี้ผมเขียนร่างไว้ตั้งแต่ปีก่อน (ตุลาคม 2025) รอบนี้เอากลับมารีไรต์ใหม่ พร้อมกับอัปเดตข้อมูลตัวเลขตลาดแรงงานและความก้าวหน้าของ AI ในแวดวงคณิตศาสตร์ช่วงปีที่ผ่านมา ตอนนั้นผมมัวแต่ตื่นตระหนกกับความเร็วในการพัฒนาของ AI จนแอบกังวลว่าสิ่งที่เขียนวันนี้จะล้าสมัยไปในวันพรุ่งนี้หรือเปล่า เลยได้แต่โพสต์ข้อความสั้นๆ ซะเยอะ แล้วแทบไม่ได้เขียนบทความยาวเป็นเรื่องเป็นราวเลย พอกลับมาเปิดอ่านดราฟต์นี้อีกทีหลังจากผ่านมาหนึ่งปี รู้สึกว่าสิ่งที่คิดไว้ตอนนั้นยังเข้าเป้าอยู่ไม่น้อย เลยจัดการขัดเกลาและปล่อยออกมาให้อ่านกัน จากนี้คงต้องกลับมาเขียนบทความยาวให้บ่อยขึ้น เพราะคอนเทนต์ที่ยังหลงเหลือ “กลิ่นอายความเป็นมนุษย์” คงจะกลายเป็นของหายากขึ้นเรื่อยๆ ในอนาคต
